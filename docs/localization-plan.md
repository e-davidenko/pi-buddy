# План локализации pi-buddy

Статус: реализовано для `ru` и `en`; ниже — исходный план и критерии.
Актуальное устройство и добавление переводов описаны в [руководстве](localization.md).
Автоматические проверки покрывают ветки TUI; проверка в живых терминалах перед выпуском остаётся ручной.

## Цель и границы первого релиза

Локализовать весь пользовательский интерфейс и речь питомца, включая обучение
и инструмент `buddy_phrases`. Добавление следующего языка должно требовать
нового каталога и регистрации локали, без изменений правил питомца.

В первый релиз входят:

- сообщения команд, подтверждения, ошибки, статистика и автодополнение;
- названия видов и взрослых форм, редкости, предметов, подписи стаи;
- общие и видовые реплики, игровые сцены и голос питомца;
- генерация и хранение пользовательских фраз с указанием языка;
- русская и английская документация.

Идентификаторы команд, видов, тем, поз, режимов и инструмента остаются стабильными:
`feed`, `veo_px`, `done`, `@stand:`, `buddy_phrases`. Существующие русские алиасы
`гав` и `голос` продолжают работать. Кличка питомца не переводится автоматически.
RTL и полноценная поддержка языков CJK — отдельное расширение после первого релиза.

`Speech` кеширует выбор без локали; `phraseProblem` возвращает русскую причину ошибки.

## 1. Выбор языка

- Добавить `/buddy lang ru|en|auto` и подсказки автодополнения. Без аргумента показывать
  выбранный режим и фактически используемый язык.
- Хранить `language: "auto" | "ru" | "en"` как общую настройку рядом с настройками
  интерфейса в `buddy.json`. Включить её в проверку, слияние `CONFIG` и сохранение при `hatch`.
- Приоритет: явно выбранный язык → язык окружения → `en`.
  Для `auto`: первое непустое значение `LC_ALL`, `LC_MESSAGES`, `LANG`;
  нормализация `ru_RU.UTF-8`/`en-US`, `C` и `POSIX` дают `en`.
  Неподдерживаемая локаль также даёт `en`.
- Для существующего состояния без поля `language` закрепить `ru`, сохранив прежнее
  поведение. Новая установка начинает с `auto`. Повреждённое поле обрабатывать
  отдельно от отсутствующего; оно не должно приводить к потере питомца.
- Язык окружения передавать через `Env`, без чтения `process.env` в домене.
- Явная настройка общая для терминалов. В `auto` фактическая локаль зависит от
  окружения конкретного процесса. Смена языка сбрасывает текущую реплику и кеши
  речи, перерисовывает питомца; обновление метаданных pi проверить отдельно.

## 2. Каталоги и архитектура

- Разместить типы каталогов и наборы `ru`/`en` в `src/content/locales/`.
  Отделить сообщения интерфейса от контента речи: `ui`, `speech`, `species`,
  `items`, `topics`. Спрайты и численные правила остаются общими.
- Использовать типизированные ключи, именованные параметры и целые предложения.
  Не собирать переводимые предложения конкатенацией фрагментов.
- Для первого релиза достаточно небольшого типизированного модуля разрешения
  локали и сообщений в приложении; внешняя runtime-библиотека пока не требуется.
- Множественное число выбирать через `Intl.PluralRules`; числа форматировать
  через `Intl.NumberFormat`. Покрыть формы для фраз, тем, дней и помощников.
- Передавать готовые наборы в существующий `SpeechEnv`. Домен речи не должен
  импортировать каталоги, окружение или файловое хранилище.
- Перенести `POSE_RU` и текст `poseNote` в слой локализованного представления.
  Валидация возвращает структурированную причину: код и параметры;
  приложение формирует сообщение на нужном языке.
- Характер вида задавать стабильными метаданными, а не поиском русских слов
  в репликах. Перед изменением существующих импортов собрать все их потребители.

## 3. Контент и резервные значения

- Перенести существующий русский контент без редактирования смысла. Английские
  реплики адаптировать под характер вида, позу и доступную ширину облачка.
- Разрешать каталог целиком: выбранная локаль поверх базового `en`. Не смешивать
  случайным образом реплики разных языков в одном пуле.
- Для отсутствующего набора брать английский набор той же темы/вида;
  далее — общий английский набор темы. Сохранить семантику `OWN_ONLY`:
  общий текст не должен приписывать питомцу чужие части тела или действия.
- Для поддерживаемых `ru`/`en` требовать полного покрытия на проверках;
  резервные значения нужны для устойчивости, а не для выпуска неполного перевода.
- Дать предметам стабильный `id`. `/buddy play` принимает id и локальные названия;
  прежние русские аргументы сохранить как алиасы. Не менять выбор игрушки молча
  из-за смены языка.
- Имена для новых питомцев выбирать из набора текущей локали. Сохранённые имена
  не менять, а существующим питомцам не пересчитывать вид или внешность.
- При смене локали очищать мешки выбора и дежурный текст `Speech`;
  голос, сцены и подписи стаи тоже должны использовать новую локаль.

## 4. Пользовательские и выученные фразы

Предлагаемый формат `buddy-phrases.json`:

```json
{
  "version": 2,
  "locales": {
    "ru": {
      "common": {
        "done": [
          "готово!"
        ]
      },
      "species": {
        "cat": {
          "hello": [
            "мяу!"
          ]
        }
      }
    },
    "en": {
      "common": {
        "done": [
          "all done!"
        ]
      },
      "species": {
        "cat": {
          "hello": [
            "meow!"
          ]
        }
      }
    }
  }
}
```

- Старый формат читать как `ru`, без определения языка по содержимому.
  При первом изменении сохранять v2 с резервной копией исходного файла.
  Чтение само по себе не переписывает файл.
- Подмешивать пользовательские фразы только активного языка. Если их нет,
  использовать встроенный контент. Не переводить пользовательский текст автоматически.
- `/buddy phrases` создаёт шаблон активного языка; `phrases clean` проверяет
  все языки, обозначая язык в отчёте. Неизвестные версии и повреждённые данные
  не перезаписывать пустым шаблоном.
- Все операции read-modify-write должны сохранять остальные локали и виды.
  Для параллельных терминалов предусмотреть атомарную запись и блокировку:
  текущий `PhraseStore` с раздельными `read`/`write` не гарантирует отсутствие потерь.
- В `/buddy learn` явно задавать язык результата, использовать примеры этого языка
  и локализованные пояснения тем. Валидацию и дедупликацию выполнять внутри локали.
- Фиксировать язык и вид в начале асинхронного обучения. Если они изменились до
  ответа модели, сохранять результат в исходный набор и сообщать это пользователю.
- Для `buddy_phrases` добавить необязательный `locale`; по умолчанию — активный.
  Обрабатывать его в момент выполнения, а не полагаться на описание, зарегистрированное
  при старте. Метаданные инструмента могут оставаться на английском, но не должны
  предписывать русский язык для всех вызовов. Проверить возможность обновления
  описания в установленном API pi до выбора механизма повторной регистрации.

## 5. Длина строк и терминал

- Зафиксировать отдельные ограничения: длина содержимого фразы и ширина вывода
  в ячейках терминала. Префикс `@pose:` не входит в видимый текст.
- Для `ru`/`en` сохранить текущий бюджет короткой реплики; убрать зависимость
  переноса и обрезки от UTF-16 `string.length` и `slice`.
- Использовать доступные в установленном TUI функции ширины и безопасной обрезки,
  предварительно проверив их экспорт. Разбиение не должно повреждать суррогатные
  пары и комбинируемые символы. Не добавлять транзитивную зависимость напрямую.
- Проверить длинные слова, имена, диалоги и статистику при узком терминале
  во всех режимах: `dock`, `compact`, `big`, `top`.
- Поддержка корректной ширины Unicode ещё не означает готовность переводов CJK
  или RTL; для них потребуется отдельная проверка переноса и направления текста.

## Последовательность реализации

1. **Основа и совместимость:** тип локали, разрешение языка, хранение настройки,
   команда `lang`, миграционные сценарии. Проверить общий прогресс между терминалами.
2. **Интерфейс:** каталоги сообщений, подписи видов и предметов, ошибки валидации,
   статистика и команды. Сохранить идентификаторы и старые алиасы.
3. **Речь:** перенести русский контент, добавить английский, внедрить разрешение
   наборов и сброс кешей; проверить игры, голос, стаю и взросление.
4. **Свои фразы и модель:** формат v2, безопасное обновление хранилища,
   язык обучения и инструмента, защита от смены вида/языка во время запроса.
5. **Проверка и выпуск:** Unicode в TUI, полное покрытие каталогов,
   `README.md` на английском и `README.ru.md` со взаимными ссылками,
   перевод `docs/behavior.md`, состав npm-пакета и заметки о миграции.

Каждый шаг — отдельное проверяемое изменение. Публичную поддержку `en` объявлять
после завершения всей цепочки, чтобы команда языка не включала частичный перевод.

## Проверки и критерии готовности

- `npm test` и `npm run typecheck` проходят.
- Контрактные проверки каталогов: одинаковые ключи интерфейса и параметры,
  все виды/темы, непустые пулы, допустимые позы, длина встроенных реплик.
- Разрешение локали: явная настройка, приоритет переменных, региональные варианты,
  `C`/`POSIX`, неподдерживаемые значения, старое состояние без настройки.
- Смена языка не сбрасывает имя, XP, шкалы, вид и прогресс; настройка сохраняется
  после перезапуска, `hatch` и слияния двух терминалов.
- Смена языка очищает текущий русский/английский текст и кеши; нет смешивания
  пользовательских наборов, ошибочной анатомии и пустых реплик при резервном выборе.
- Старые файлы фраз читаются без изменений; миграция сохраняет данные;
  изменения одного языка не теряют другой и параллельные записи.
- Обучение проверяется через подставной `ModelPort`, включая смену вида/языка
  во время запроса. Качество английских формулировок проверяется вручную.
- Ручная проверка обоих языков во всех режимах TUI и на узкой ширине;
  отдельные случаи для кириллицы, emoji и комбинируемых символов.
- `npm pack --dry-run` включает новые каталоги и документы; чтение и выбор языка
  не требуют сети или обращения к модели.

## Решения, которые можно уточнить перед реализацией

Предлагаемые значения по умолчанию: два языка `ru`/`en`, единый язык интерфейса
и речи, общая настройка между терминалами, сохранение русского для старых установок,
`auto` для новых. Раздельные `uiLanguage`/`speechLanguage`, дополнительные языки
и внешняя платформа переводов пока не нужны; вводить их при конкретной потребности.

## Уточнения реализации

Русские каталоги сохранены в существующих content-модулях, английский — в `content/locales/en.ts`.
Общие сообщения обоих языков — в `content/locales/ui.ts`. При недостающей видовой
теме английский использует нейтральную общую реплику. Внешний i18n-пакет не добавлен.
Описание команды при регистрации двуязычное; подсказки и ответы используют текущую
локаль. Контекст языка для инструмента обновляется перед запросом агента,
поэтому повторная регистрация не требуется. Занятый файл фраз возвращает ошибку
с предложением повторить команду; потерянные блокировки восстанавливаются по PID.
